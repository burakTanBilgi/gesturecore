gesturecore bench

A workbench for gesturecore, a small library that turns camera hand tracking into clean gesture events: pinches, poses, movements. The bench shows everything the library sees and thinks, and lets you tune it live and design new gestures. The camera stays running on the left while you read.

1. Quick start

  1. Press Start camera (top right) and allow camera access.
  2. Raise only your right hand. Its label on the video should say Right. If it says Left, tick swap L/R in the header.
  3. Hold an open palm toward the camera. A teal ring fills around your palm; when it closes the hand is engaged.
  4. Touch your thumb tip to a fingertip and hold. A small pink ring fills between them; when full you get pinch:start with the finger's name in the Events log.
  5. Open the Scroll test tab, engage, pinch, and move your hand up and down to scroll the text.
  6. Try a quick sideways swipe (engaged, not pinching): motion swipeLeft / swipeRight appears in the log.
Nothing here is saved on a server. Slider positions, gestures and session history live in this browser only (see Files and saving).

2. How it works

Every camera frame goes through the same one-way pipeline:

Cameraa video frame
→
MediaPipefinds up to 2 hands, 21 points each, plus a Left/Right guess
→
Bench adaptermirrors the view, fixes the label, adds a timestamp
→
SmoothingOne Euro filter on every point
→
Featurescurls, pinch distances, openness, tilt, size…
→
Rules + timersposes, engage, pinch, movements, loss
→
Eventsshown in the log and used by the scroll demo

The blue-bordered boxes are gesturecore itself. It has no idea there is a camera, a browser or a screen: it receives 21 points per hand and a time, and returns a list of events. That is what lets the same library drive a browser-control tool, a music instrument, or run in Node tests with no camera at all. Everything else on this page (camera, drawing, sliders, storage) is the bench, which is just the first program using the library.

Gestures are geometric rules, not machine learning. MediaPipe does the hard part (finding the hand); gesturecore only measures angles and distances and applies thresholds and timers. So every decision is explainable: the readout column shows the exact numbers each rule looks at.

Two ideas used everywhere

  • Hysteresis: an on/off decision uses two thresholds, one to switch on and a looser one to switch off. A value hovering near a single line would otherwise flicker on-off-on every frame.
  • Dwell: a state has to hold continuously for some time (default 300 ms) before its event fires. Any frame that breaks it resets the timer to zero. The filling rings on the video are these timers.

3. Hand measurements

MediaPipe gives 21 points per hand. Tips are 4 8 12 16 20 (thumb → pinky), knuckles (MCP) 1 5 9 13 17, middle joints (PIP) 2 6 10 14 18.

Span (teal) is the wrist-to-middle-knuckle length. Every distance is divided by the span, so a pinch or a swipe measures the same whether your hand is near the camera or far away. Distances in the docs are therefore in hand-size units: 1.0 = one span.

FeatureRangeWhat it is
curl (×5)0 … 1How bent each finger is: the angle at its middle joint, 0 = straight, 1 = fully bent. The thumb uses joint 3 and is noisier. The mapping from angle to 0…1 is set by the finger straight / bent sliders.
openness0 … 11 − the average curl of index…pinky. 0 = fist, 1 = all fingers straight.
pinchRaws0 … ~1.5Thumb-tip to each fingertip distance, in spans (pink dashed line). About 0.1 when touching.
pinch0 … 1Thumb↔index distance rescaled between the closed and open sliders: 0 = touching, 1 = wide open.
tilt−180° … 180°Palm rotation on screen: direction from wrist to middle knuckle. 0 = fingers up, positive = leaning right.
span~0.1 … 0.5Hand size on screen. Bigger = closer to the camera.
centroid0 … 1Palm centre (wrist + four knuckles) as a fraction of the frame. Used for scrolling and movements.

The depth value z from MediaPipe is noisy, so it is only used inside joint angles, never as a distance. Features are computed after smoothing.

4. Engagement

Engagement is a safety catch. A hand in view is not trusted to do anything until it shows the engage pose (default: open palm, held for 500 ms). Until then:

  • pinch and movement events never fire;
  • pose events still fire (they only describe the hand shape).

Once engaged, the hand stays engaged whatever it does, until it leaves the camera view (see Losing a hand). This is what stops typing, scratching your face or reaching for a mug from scrolling a page.

On screen: the teal outer ring fills while you hold the engage pose; the hand's badge reads engaged when done. Change the pose or turn the catch off in Tuning → Timing → engage pose ("none: always engaged").

5. Pinch

For each enabled finger the library measures the thumb-tip distance (in spans). With the default sliders:

StepRule
closethe nearest enabled finger comes below 0.20 (closed + hysteresis). The pink ring appears.
settlewhile the ring fills, the thumb may slide to a neighbouring finger; the nearest one is the candidate and the timer keeps running.
startthe thumb has stayed closed for 300 ms (dwellMs) and the hand is engaged → pinch:start with finger. That finger is now locked.
moveevery following frame → pinch:move with the same finger and a 0…1 value.
endthat finger's distance goes above 0.30 (closed + 3×hysteresis), the hand is lost, or the finger is unticked → pinch:end.

If the thumb opens again before the 300 ms are up, nothing fires and the timer resets. Enable or disable fingers in Tuning → Pinch → pinch fingers.

6. Poses (hand shapes)

A pose is a list of allowed curl ranges per finger. Fingers not listed are ignored.

{ "name": "fist", "fingers": {
    "index":  { "curl": [0.75, 1] }, "middle": { "curl": [0.75, 1] },
    "ring":   { "curl": [0.75, 1] }, "pinky":  { "curl": [0.75, 1] } } }
  • Score: each listed finger scores 1 if its curl is inside the range, fading to 0 when it is pose falloff (0.15) outside. The pose score is the average. See the ≈ scores rows in the readout.
  • Held pose: the highest-scoring pose that reaches its minScore (default 0.8). Its name is on the hand's badge and highlighted in amber in the readout.
  • Event: when the held pose stays the same for dwellMs (300 ms), a single pose event fires. It fires again only after the pose changes. The amber ring is this timer.

Built in: fist, openPalm, point. Make your own in the Gestures tab: Record a pose reads your real finger curls over 15 frames and saves ranges of curl ± tolerance. A larger tolerance is more forgiving but may overlap other poses; include the thumb only when it matters (e.g. thumbs-up).

7. Movements

A movement describes how the palm centre travels. It fires once when satisfied, and only while engaged and not pinching (so a pinch-drag scroll never counts as a swipe, even right after you let go).

FieldMeaning
axisx sideways · y up/down · depth toward/away from the camera (hand gets bigger/smaller) · tilt twisting the palm
direction1 = right / down / toward camera / clockwise on screen; -1 = the opposite. Left/right are as you see them with mirror view on.
distancehow far one stroke must go: spans for x and y; relative size for depth (0.25 = 25 % bigger); radians for tilt (0.5 ≈ 29°)
withinMsthe whole movement must fit in this time, so slow drifting does not count
reversals0 = one stroke (swipe, push, twist). 3 = four strokes back and forth (a wave); direction is then ignored
poseoptional: only movement made while holding this pose counts
cooldownMsoptional: minimum time before the same movement can fire again (default 500)
{ "name": "swipeUp", "axis": "y", "direction": -1, "distance": 1.5, "withinMs": 400 }
{ "name": "wave", "axis": "x", "reversals": 3, "distance": 0.5, "withinMs": 1500, "pose": "openPalm" }
{ "name": "push", "axis": "depth", "direction": 1, "distance": 0.3, "withinMs": 500 }

Built in: swipeLeft, swipeRight (1.5 hand-lengths within 400 ms) and wave. The ↝ rows in the readout show each movement's progress from 0 to 1; watch them while you move to see how close you are, then adjust distance or time. Build new ones with the Build a movement form.

8. Losing a hand

If a hand disappears for more than 150 ms (lostAfterMs), the library closes everything in order: pinch:end (if pinching), disengage (if engaged), then lost, and forgets that hand. A shorter gap (a finger passing in front, a blurry frame) changes nothing, so a drag survives brief occlusion. Raise the value if tracking drops out a lot; lower it if a hand that left the frame feels "sticky".

10. The tabs

Tuning

A control for every library setting. Drag a slider or type a number; it applies on the next frame. A • after a label means it differs from the default. Reset all to defaults, Copy config JSON (to keep or share a tuning), Import JSON… (paste one back).

SettingDefaultEffect
minCutoff1.0 Hzsmoothing when the hand is still. Lower = steadier but laggier.
beta0.007how much smoothing relaxes during fast movement. Higher = less lag on quick motions. The default is very low; 5–20 is worth trying.
dCutoff1.0 Hzsmoothing of the speed estimate used by beta. Rarely needs changing.
pinch fingersallwhich fingers can pinch
closed0.15thumb distance counted as touching. Close line = closed + h, release line = closed + 3h.
open0.75distance counted as fully open (only affects the 0…1 pinch value)
hysteresis h0.05gap between close and release lines. Bigger = less flicker, but harder to release.
engage poseopenPalmthe pose that engages a hand, or none
dwellMs300hold time for pinch start and pose events
engage dwellMs500hold time for engaging
lostAfterMs150how long a hand may vanish before it is dropped
finger / thumb straight, bent0.25 / 2.4, 0.2 / 1.4 radjoint angles that count as curl 0 and curl 1. If your straight fingers show curl 0.2, raise straight; if a tight fist shows 0.6, lower bent.
pose falloff0.15how fast a finger's score drops outside its range. Bigger = more forgiving poses.

Gestures

Record a pose from your hand: name it, pick the hand, press Record, make the shape during the countdown and hold still. Build a movement: fill in the form (see Movements) and press Add. A pose or movement with an existing name is replaced. Both lists can also be edited as JSON below; Apply checks the JSON and explains what is wrong if anything is.

Scroll test

A demo of the browser-control use case plus the measurement for "fewer than 2 accidental pinches per 10 minutes".

  • Pinch to scroll: engage, pinch, move your hand up/down like dragging paper. hand and pinch finger choose what may scroll; gain is how far the page moves per hand movement; invert flips direction.
  • False-activation session: press Start session and use the computer normally for at least 10 minutes: type, reach, rest, and scroll on purpose sometimes. Every time a pinch starts that you did not intend, press F. After 10 minutes it shows PASS (< 2 per 10 min) or FAIL. Finished sessions are listed underneath.

Fixtures

For the automated tests. Choose a name (open, fist, point, pinch or custom) and hand, press Capture, hold the pose. The 21 points are averaged over several frames, previewed with their feature values and pose scores, and Save to test/fixtures writes the file into the project. Then run the tests (run-tests.cmd). The shipped fixtures are synthetic placeholders, so capturing real ones is recommended.

Source

Camera device and resolution (lower resolution can raise fps), GPU/CPU, and MediaPipe's own confidence thresholds: detection (finding a new hand), presence (deciding a tracked hand is still there), tracking (trusting frame-to-frame tracking). Raising them reduces phantom hands but drops real ones more often. Overlay toggles hide the raw skeleton, smoothed skeleton or the image.

11. Tuning guide

SymptomTry
Skeleton jitters when stilllower minCutoff
Skeleton trails behind fast movementraise beta (try 5, then 20)
Pinch feels slow to startraise beta; lower dwellMs (e.g. 200)
Pinch doesn't trigger although fingers touchwatch the thumb→ bars: if they never cross the white tick, raise closed
Accidental pincheslower closed, raise dwellMs, untick fingers you don't use, keep engagement on
Pinch drops during a dragraise hysteresis; raise lostAfterMs if the hand flickers out
Wrong pose, or flickering between posescheck curl bars; adjust finger straight/bent, narrow the pose ranges, or raise its minScore
Pose never recognisedraise pose falloff, widen ranges, or re-record it with more tolerance
Swipe doesn't firewatch its ↝ bar: lower distance or raise withinMs; make sure you are engaged and not pinching
Swipe fires by accidentraise distance, lower withinMs, or require a pose
Left/right swipes reversedturn mirror view on

Change one thing at a time and watch the readout numbers. When a tuning feels right, Copy config JSON and keep it: those values become the library defaults.

12. Using it in code

import { GestureCore } from 'gesturecore';

const core = new GestureCore({ aspect: 640 / 480, engage: { pose: 'openPalm', dwellMs: 500 } });

// every frame: hands from MediaPipe, time in milliseconds
for (const e of core.update(hands, performance.now())) {
  if (e.type === 'pinch:start') console.log(e.hand, 'pinched', e.finger);
  if (e.type === 'motion' && e.name === 'swipeLeft') history.back();
}

core.getFeatures('Right');   // latest measurements, or null
core.getHandState('Right');  // engaged, timers, pose scores, movement progress
core.setConfig({ dwellMs: 200 });   // live change, same as the sliders

Every event has type, hand ('Left' | 'Right') and t. Within one frame, hands come Left then Right. Every pinch:start gets exactly one pinch:end and every engage one disengage. The config is plain JSON, exactly what Copy config JSON gives you. More in README.md.

13. Troubleshooting

"Camera permission was denied"click the camera icon in Chrome's address bar, allow, then Start camera again
Black video / camera busyanother app (Teams, Zoom, Camera) may hold the camera; close it. Or pick the right device in Source.
Low fpsSource → resolution 320×240; close other tabs; check delegate says GPU
Hand labelled wrong sidetick swap L/R
Nothing engagesTuning → engage pose: if it says "(missing!)" that pose was deleted; pick another or none
Hands flicker in and outbetter lighting, plain background; lower detection/presence confidence slightly; raise lostAfterMs
Could not start: model / wasm errorthe model file is missing: close the bench window and run run-bench.cmd again (it downloads the model if absent)
Everything feels off after experimentingTuning → Reset all to defaults; Gestures → reset poses / movements; R resets tracking

Keys (ignored while typing in a field): F mark a false activation (during a session) · R reset tracking · Space pause/resume detection.

14. Files and saving

  • Saved in this browser (localStorage for localhost:5173): the config (sliders, poses, movements), bench settings (tab, toggles, camera choice), and session history. A different browser starts from defaults. Clearing site data resets everything.
  • Written to the project: only fixture captures (test/fixtures/*.json).
  • Project layout: src/ the library (no browser code allowed), test/ automated tests, bench/ this page, README.md developer notes.
  • Start / test: double-click run-bench.cmd or run-tests.cmd in the Projects folder.
